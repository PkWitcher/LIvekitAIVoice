Voice Agent — Vobiz Integration Status Report

Nova AI Voice Agent (LiveKit + Vobiz SIP) • Generated 19 Nov 2026

This report summarizes what is already implemented in the voice agent platform, what still needs to be built to fully answer Vobiz/Rudra's integration questions (SIP trunking, API/webhooks, sub-accounts, number provisioning), and what is blocked on external approvals rather than engineering effort.

1. What We Have Completed

SIP TrunkingDone
Outbound SIP trunk to Vobiz is auto-created/reused on startup (backend/setup_sip_trunk.py), configured with TCP transport, and the trunk ID is written out for the agent to pick up automatically.
Outbound Calling APIDone
Two routes: /api/dispatch (dashboard, session-authenticated) and /api/public/calls (API-key authenticated, for n8n / Make / Zapier / Meta Lead Ads and other custom integrations).
Call Events / Status TrackingDone
/api/webhook/livekit consumes LiveKit's own webhooks (participant_joined / participant_left / room_finished) to track call lifecycle and trigger downstream actions.
Call RecordingDone
LiveKit Egress starts on participant join and stops on call end; the recording is uploaded to Supabase S3-compatible storage.
Call Transcripts & AI SummaryDone
A full transcript is stored per call; AI classifies disposition and interest, extracts the appointment date, and generates a summary automatically.
Outbound Webhooks (to customers)Done
Customers can register their own webhook URLs; HMAC-signed payloads are delivered on call.completed (and related) events.
API Key ManagementDone
Customers can generate/revoke their own API keys to trigger calls programmatically (api_keys tab in Settings > Integrations).
WhatsApp NotificationsDone
An automated WhatsApp message is sent after each call via Wampli, including the call outcome.
Google Sheets Write-backDone
Call outcome (interested, appointment date, disposition, summary) is written back into the originating Google Sheet row.
Usage & Subscription LimitsDone
Per-user plan with calls_used / minutes_used enforcement before allowing new outbound calls.

2. What We Still Need to Create

DTMF HandlingCode now
No DTMF capture exists today. Needs LiveKit SIP DTMF event handling added to backend/agent.py so keypad input during a call can be read and acted on.
Vobiz-native Webhook ReceiverCode + spec
We currently rely only on LiveKit's own webhooks. If Vobiz needs to push call-event/recording notifications directly to us, we need a dedicated receiver endpoint built against Vobiz's payload format.
Programmatic Number ProvisioningBlocked on credentials
Vobiz's Calls/Account/Trunks REST API (https://api.vobiz.ai/api/v1) needs an X-Auth-ID / X-Auth-Token pair issued to us before we can provision numbers programmatically.
Sub-accounts / Reseller ModelBlocked on approval
Vobiz natively supports sub-accounts (own Auth ID/Token, numbers, usage per child account), but we need Vobiz's confirmation and Partner API access before we can create and manage them programmatically.
Per-customer Outbound RoutingCode, after above
Today all customers share one Vobiz trunk and one outbound number. Once sub-accounts exist, each customer/org can be routed through its own trunk and number.
Reseller / Partner PricingBusiness step
Not a code item. Vobiz requires our detailed use case, target countries, and expected call volume before they can quote reseller/partner pricing.

3. Dependencies Before the Remaining Items Can Work

  • Obtain the Vobiz Console Auth ID and Auth Token (X-Auth-ID / X-Auth-Token) for REST API access — separate from the existing SIP trunk username/password.
  • Get confirmation / access to the Partner API from Vobiz if we want to create sub-accounts programmatically, rather than manually via the Console.
  • Share our use case, target countries, and expected call volume with Vobiz so they can quote reseller/partner pricing (already requested in our reply to Rudra).
  • If a native Vobiz webhook receiver is required, get the exact payload and signature spec from Vobiz docs/support before building it.
  • All new integrations should be tested against Vobiz's sandbox/live API with a real test call before being considered production-ready.

  3. Once Auth ID/Token are issued, wire up programmatic number provisioning.
  4. Design the sub-account ↔ internal org/user mapping once Partner API access is confirmed.
